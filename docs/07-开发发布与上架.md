# 开发发布与上架

使用 Node.js25 和 npm ci 固定依赖。构建先核验 vendor/sources.json，再编译静态 Schema 校验器、后端、React、Skill与功能清单。运行包带完整许可，不含作者数据或凭据，不执行安装脚本。

```bash
npm ci
npm run build
npm run check
npm run test:unit
npm run test:machine
npm run test:ui
npm run package
```

测试只使用隔离作品；HETU_SOURCE、HETU_TEST_BIN、HETU_TEST_PACKAGE 和 HETU_PACKAGED_APP 固定真实宿主与包路径。机器与正式安装分别取证。

发行固定源码提交、不可变Tag、运行包、归档及包摘要、许可和实际验收回执。下载后重新核验同一字节，再登记河图插件中心。功能、专业数据和方法由本包维护；宿主只维护公共发现入口。安装、发布和作者业务决定分别授权，不用发行权限代替创作采纳。

## 可复跑验收

源码CI使用Node25、锁文件、静态Schema、类型、单元、文档与运行包构建。正式安装验收由 `acceptance-lock.json` 固定宿主提交、公开归档摘要及插件包摘要，通过 `Official host acceptance` 手动工作流运行；不编译或替换宿主。脚本 `scripts/accept-installed.py` 校验签名、公证、Gatekeeper和精确包字节，再执行全部机器与Electron旅程。书稿交付仓库还串联六插件、两个独立作品、实际系统语音及离线播放器。

本机已独立安装并核验同版宿主时可设置 `HETU_REUSE_APP=1`；使用公开发行包复验时设置 `HETU_PUBLISHED_BUNDLE=1`。本机复用不绕过版本、签名和摘要核验。默认脚本只在干净CI安装，不覆盖未知应用。

## 本地集成前提

纯构建、类型与单元不要求运行河图。`test:machine`和`test:ui`需要先准备宿主测试依赖与机器二进制：`HETU_SOURCE`指定确切宿主checkout；源码构建时`HETU_TEST_BIN`指定该构建的bin目录，桌面资源也须来自同一份源码。使用正式安装包时同时指定`HETU_PACKAGED_APP`及随包`HETU_TEST_BIN`，测试会拒绝缺少随包入口的安装验收，并清除开发运行器覆盖。

测试自动建立隔离协作目录、作品和安装状态。正常业务全部经CLI/MCP；Electron只验收审阅、播放、导出对话框、冲突和缓冲恢复。安装源码目录或检查manifest不能代替运行包验收。
